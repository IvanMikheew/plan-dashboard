# tools/avito_stats.ps1 — сбор статистики Авито (Business API) в CSV
# tools/calendar_stats.ps1 — записи клиентов из Google Calendar в CSV

Назначение: посуточная статистика объявления (показы, просмотры, контакты) через
официальное Avito API (`api.avito.ru`), дописывание строк в дневник замеров CSV.

## Запуск

```powershell
powershell -ExecutionPolicy Bypass -File tools\avito_stats.ps1 -DateFrom 2026-11-15 -DateTo 2026-11-24
powershell -ExecutionPolicy Bypass -File tools\avito_stats.ps1 -DateFrom 2026-11-25 -DateTo 2026-11-30 -ItemId 8547421312
```

Параметры: `-DateFrom`, `-DateTo` (обязательные, `yyyy-MM-dd`), `-ItemId`
(по умолчанию 8547421312), `-EnvPath`, `-CsvPath`, `-RawDir`, `-NoCsv`
(только скачать сырьё, CSV не трогать). Повторный запуск **обновляет** CSV
(upsert): показы/просмотры/контакты существующих строк перезаписываются, только
если новое значение **строго больше** записанного (Avito отдаёт свежие даты с
задержкой T+1 — 0 означает «ещё не посчитано» и в пустую ячейку не пишется,
пусто = «ожидают API», в дашборде «—», а не 0). Колонки
`записи`/`записи_старые`/`записи_новые` (ручные данные владельца) не трогаются,
строки сортируются по дате.

## Зависимости

Windows PowerShell 5.1+ (или pwsh), доступ в интернет. Ничего устанавливать не нужно.

## Переменные окружения (только имена)

Файл `.env` (путь задаётся `-EnvPath`, по умолчанию `C:\Users\user\Desktop\opencode\.env`):
`AVITO_CLIENT_ID`, `AVITO_CLIENT_SECRET`. Значения скрипт читает сам при запуске,
никогда не печатает и не пишет в файлы. Держать `.env` вне git.

## Что делает (эндпоинты Avito Business API)

1. `POST /token` — авторизация client_credentials.
2. `GET /core/v1/accounts/self` — user_id аккаунта (сохраняется только id, без email/телефона).
3. `POST /stats/v2/accounts/{user_id}/items` — метрики по дням (grouping=day)
   и по объявлениям (grouping=item): impressions, views, contacts и др.
   Rate limit: 1 запрос/мин — скрипт ждёт и повторяет при HTTP 429.
4. `POST /stats/v1/accounts/{user_id}/items` — посуточные счётчики по объявлению
   (uniqViews, uniqContacts, uniqFavorites) — кросс-проверка.
5. `POST /core/v1/accounts/{user_id}/calls/stats/` — статистика звонков.

Сырые ответы (JSON) сохраняются в `отчёты\avito-api-raw\`.

## CSV

Файл `отчёты\статистика-авито.csv`, схема:
`дата,объявление_id,показы,просмотры,контакты,записи,записи_старые,записи_новые,источник`

- показы = `impressions` (показы в поиске/рекомендациях, уникальные по юзеру/сутки);
- просмотры = `views` (совпадает с v1 `uniqViews`);
- контакты = `contacts` (посмотрели телефон + написали в чат, уникальные по юзеру/сутки);
- `записи_старые`/`записи_новые` = записи клиентов из Google Calendar по пометкам
  «старый»/«новый» в названии события (см. `calendar_stats.ps1`);
- `записи` — сумма колонок `записи_старые` и `записи_новые`, только если она > 0
  (0 пометок = данных нет, не ноль — колонка остаётся пустой);
- источник — `avito-api`.

## calendar_stats.ps1 — записи из Google Calendar

Скачивает ICS по ссылке `CALENDAR_ICS_URL` (только из `.env`, значение не логируется
и не коммитится), парсит VEVENT: развёртывает RRULE (FREQ/INTERVAL/COUNT/UNTIL),
учитывает EXDATE, исключения RECURRENCE-ID и отмены (STATUS:CANCELLED), часовой
пояс — Asia/Krasnoyarsk (UTC «Z» → +7 ч). Для диапазона дат считает по дням события,
в названии которых есть «новый» или «старый» (регистр не важен; пишутся также
«новая/новые», «старая/старые»), и обновляет колонки CSV.

```powershell
powershell -ExecutionPolicy Bypass -File tools\calendar_stats.ps1 -From 2026-11-15 -To 2026-11-24
powershell -ExecutionPolicy Bypass -File tools\calendar_stats.ps1 -NoUpdate   # только отчёт, CSV не трогать
```

Параметры: `-From`, `-To` (`yyyy-MM-dd`, по умолчанию — все даты CSV), `-CsvPath`,
`-EnvFile`, `-NoUpdate`. Идемпотентен: повторный запуск не меняет файл.
В лог не попадают названия событий (в них имена клиентов). Пометка сама по себе
означает запись — событие дополнительно не фильтруется по слову «массаж».
Для тестов `CALENDAR_ICS_URL` может быть локальным путём к `.ics`-файлу.

Метрики v2 считаются на весь профиль аккаунта. Если в периоде активно более одного
объявления, скрипт пишет просмотры/контакты из v1 (по объявлениям), а показы
оставляет пустыми — см. следующий раздел (это лечится `avito_fill_impressions.ps1`).

## Почему показы пустые при нескольких объявлениях (и как добрать)

Проверено по OpenAPI-спеке (`MissiaL/avito-api`, `references/avito-api-openapi.json`)
и зондом `tools/avito_probe.ps1`:

- `stats/v2` — **только по профилю**: в схеме `AnalyticsRequest` поля фильтра по
  объявлениям нет (`filter` умеет только categoryIDs/employeeIDs), присланный
  `itemIds` API молча игнорирует (проверено: ответ совпал с профилем);
  `grouping` ∈ day|week|month|item|totals — комбинации «объявление × день» нет;
- `stats/v1` — показов не отдаёт вообще (поля только uniqViews/uniqContacts/
  uniqFavorites; `impressions`/`uniqImpressions` → HTTP 400);
- **показы объявления за конкретный день** даёт `stats/v2` с `grouping=item`
  и диапазоном «один день» — по одному запросу на день (rate limit 1/мин).

`tools/avito_fill_impressions.ps1` добирает именно так:

```powershell
powershell -ExecutionPolicy Bypass -File tools\avito_fill_impressions.ps1 `
  -DateFrom 2026-11-09 -DateTo 2026-11-14
```

Заполняет ячейки колонки `показы` за диапазон **правилом «новое > записанного»**
(пусто = 0): пустые заполняются, устаревшие (T+1) освежаются, 0 от API не
записывается — ячейка остаётся пустой («ожидают API»). Флаг `-Overwrite`
заставляет обрачиваться и за непустыми ячейками (освежение); без него — только
пустые. Остальные колонки и ручные значения владельца не трогаются, затем
строки CSV сортируются по дате. `-DryRun` — показать цели без запросов.
Сырые ответы — `отчёты\avito-api-raw\fill_v2_item_*.json`.
Скорость: ~1 минута на день из-за rate limit (4 дня ≈ 4 минуты).

## Ограничения API (проверено по спеке и прогоном)

- Глубина данных: 270 дней; v2: не более 1000 сущностей в ответе.
- «Долистали до конца», источники просмотров, поисковые запросы — API не отдаёт
  (нет методов), есть только в личном кабинете Авито.
- Звонки: `calls/stats` отдаёт данные только по звонкам через Авито (calltracking).
