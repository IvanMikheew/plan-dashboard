# plan-dashboard — план за паролем (GitHub Pages)

Публичная страница, где лежит **зашифрованный план владельца**. Ссылку может открыть
любой, но видит только окно с паролем: без пароля содержимое не расшифровать.

- Репозиторий: <https://github.com/IvanMikheew/plan-dashboard>
- Страница (GitHub Pages): <https://ivanmikheew.github.io/plan-dashboard/>

## Как это работает

1. `data/plan.enc` — зашифрованный markdown-план. Файл публичный, но бесполезный без пароля.
2. `index.html` — страница с полем пароля. Пароль вводит только владелец; он нигде не хранится
   (не в репозитории, не в `.env`, не в localStorage). Расшифровка идёт в браузере через WebCrypto.
3. `tools/sync_plan.ps1` — автозаливка: шифрует локальный `ПЛАН.md` и коммитит
   `data/plan.enc` в репозиторий через GitHub API.

## Как обновить план

Нужны: Windows PowerShell, Node.js 18+, токен GitHub (`GITHUB_TOKEN`) в `.env`.

```powershell
cd C:\Users\user\Desktop\opencode\plan-dashboard
$env:PLAN_PASSWORD = '...'          # пароль владелец вводит сам в своей сессии
.\tools\sync_plan.ps1               # шифрует ПЛАН.md → коммитит data/plan.enc
```

- Пароль передаётся **только** переменной окружения `PLAN_PASSWORD` — не аргументом, не файлом.
- Путь к плану по умолчанию: `C:\Users\user\Desktop\ПЛАН.md` (параметр `-PlanPath`, если другой).
- Смена пароля = просто запустить `sync_plan.ps1` заново с новым `PLAN_PASSWORD`
  (старый пароль перестаёт открывать страницу).
- GitHub Pages собирает обновление 1–2 минуты.

## Формат данных (контракт с дизайнером UI)

`data/plan.enc` — текстовый файл, содержимое: `base64` байтов

```
16 байт: salt   (случайная соль, на каждое шифрование своя)
12 байт: IV     (случайный вектор, на каждое шифрование свой)
N байт : ciphertext ‖ 16 байт auth-tag   (AES-256-GCM)
```

- Ключ: `PBKDF2-HMAC-SHA256(password, salt, 200000 итераций, 32 байта)`.
- Открытый текст: UTF-8 markdown.
- Расшифровка в браузере: WebCrypto (`deriveKey` PBKDF2 → `decrypt` AES-GCM),
  при неверном пароле `decrypt` бросает исключение → показывать «Неверный пароль».
- Расшифрованный markdown рендерится в `<div id="content">`.
- Кэширование расшифрованного текста запрещено (localStorage — нельзя; максимум —
  память страницы или sessionStorage с автоочисткой).

Этот формат закреплён в `index.html` (комментарий «КОНТРАКТ С ДИЗАЙНЕРОМ») и в
`tools/crypt.js`. Менять формат = ломать и страницу, и заливку одновременно.

## Структура репозитория

```
index.html          — страница-заглушка с парольным экраном (дизайнер делает финальный UI)
data/plan.enc       — зашифрованный план (генерируется sync_plan.ps1)
tools/crypt.js      — шифрование/расшифровка (Node, без зависимостей)
tools/sync_plan.ps1 — автозаливка плана в репозиторий
README.md           — этот файл
```

## Безопасность

- Пароль владелец держит сам: не в репо, не в `.env`, не в скриптах, не в логах.
- Соль и IV случайные при каждом шифровании — один и тот же план даёт разный шифротекст.
- AES-256-GCM с auth-tag: неверный пароль и порча файла дают одну ошибку — «неверный пароль».
- Страница отдаётся по HTTPS; расшифровка только на клиенте, сервер plaintext не видит.
- Ограничение: пароль можно перебирать брутфорсом (файл публичный) — используйте длинный
  пароль (12+ символов).
