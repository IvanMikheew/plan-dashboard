# plan-dashboard — план за паролем (GitHub Pages)

Публичная страница, где лежит **зашифрованный план владельца**. Ссылку может открыть
любой, но видит только окно с паролем: без пароля содержимое не расшифровать.

- Репозиторий: <https://github.com/IvanMikheew/plan-dashboard>
- Страница (GitHub Pages): <https://ivanmikheew.github.io/plan-dashboard/>

## Как это работает

1. `data/plan.enc` — зашифрованный markdown-план. Файл публичный, но бесполезный без пароля.
2. `index.html` — страница с полем пароля. Пароль вводит только владелец; он нигде не хранится
   (не в репозитории, не в `.env`, не в localStorage). Расшифровка идёт в браузере через WebCrypto.
3. `tools/sync_plan.ps1` — автозаливка: шифрует локальный `ПЛАН.md` и коммитит
   `data/plan.enc` в репозиторий через GitHub API.

## Как обновить план

Нужны: Windows PowerShell, Node.js 18+, токен GitHub (`GITHUB_TOKEN`) в `.env`.

```powershell
cd C:\Users\user\Desktop\opencode\plan-dashboard
$env:PLAN_PASSWORD = '...'          # пароль владелец вводит сам в своей сессии
.\tools\sync_plan.ps1               # шифрует ПЛАН.md → коммитит data/plan.enc
```

- Пароль передаётся **только** переменной окружения `PLAN_PASSWORD` — не аргументом, не файлом.
- Путь к плану по умолчанию: `C:\Users\user\Desktop\ПЛАН.md` (параметр `-PlanPath`, если другой).
- Смена пароля = просто запустить `sync_plan.ps1` заново с новым `PLAN_PASSWORD`
  (старый пароль перестаёт открывать страницу).
- GitHub Pages собирает обновление 1–2 минуты.

## Формат данных (контракт с дизайнером UI)

`data/plan.enc` — текстовый файл, содержимое: `base64` байтов

```
16 байт: salt   (случайная соль, на каждое шифрование своя)
12 байт: IV     (случайный вектор, на каждое шифрование свой)
N байт : ciphertext ‖ 16 байт auth-tag   (AES-256-GCM)
```

- Ключ: `PBKDF2-HMAC-SHA256(password, salt, 200000 итераций, 32 байта)`.
- Открытый текст: UTF-8 markdown.
- Расшифровка в браузере: WebCrypto (`deriveKey` PBKDF2 → `decrypt` AES-GCM),
  при неверном пароле `decrypt` бросает исключение → показывать «Неверный пароль».
- Расшифрованный markdown рендерится в `<div id="content">`.
- Кэширование расшифрованного текста запрещено (localStorage — нельзя; максимум —
  память страницы или sessionStorage с автоочисткой).

Этот формат закреплён в `index.html` (комментарий «КОНТРАКТ С ДИЗАЙНЕРОМ») и в
`tools/crypt.js`. Менять формат = ломать и страницу, и заливку одновременно.

## Статистика Авито (avito.html)

Вторая страница того же дашборда: **авито-метрики за период** за тем же паролем.

- `avito.html` — страница (**v2**): блок «Успеваемость к цели», фильтр периода,
  строка-вывод (тренд), 9 KPI-плашек с меткой периода и 7-дневной строкой
  «за 7 дней: X · к прошлой нед. ±Y%», график (чистый canvas) по окну фильтра,
  таблица по дням с пагинацией по 31 строке (колонки записей новых/старых —
  редактируемые ячейки, колонка «К→З»). Ссылка «← План» внизу;
  в `index.html` — ссылка «Статистика Авито».
- `data/avito.enc` — зашифрованные данные: JSON `{updated, rows[], edits[]}`
  (rows — из `отчёты\статистика-авито.csv`, включая `bookingsOld`/`bookingsNew`,
  edits — даты из `журнал-изменений.md`).
- `tools/sync_avito.ps1` — шифрует CSV → `data/avito.enc` **тем же паролем** (`PLAN_PASSWORD`)
  и коммитит через GitHub API. Перед шифрованием запускает `tools/calendar_api.ps1`
  (свежие записи из Google Calendar по пометкам «новый»/«старый» в событиях:
  веб-API Apps Script — `CALENDAR_API_URL` в `.env`, см. `tools/apps_script_setup.md`;
  если URL не задан или запрос упал — автоматический фолбэк на ICS
  `CALENDAR_ICS_URL`, ошибка календаря не прерывает заливку).
  Флаг `-LocalOnly` — записать файл локально без коммита.

Как обновить статистику (нужны PowerShell, Node.js 18+, `GITHUB_TOKEN` в `.env`):

```powershell
cd C:\Users\user\Desktop\opencode\plan-dashboard
$env:PLAN_PASSWORD = '...'          # тот же пароль, что у плана
.\tools\sync_avito.ps1               # CSV → JSON → шифр → коммит data/avito.enc
```

Путь к CSV по умолчанию: `C:\Users\user\Desktop\opencode\отчёты\статистика-авито.csv`
(параметр `-CsvPath`). Переход «План ⇄ Статистика» в одной вкладке — авто-вход
(общий ключ sessionStorage).

### Дашборд v2: фильтры, пагинация, окна KPI, цель (2026-11-26)

- **Фильтр периода** (под шапкой): «Всё время» (дефолт) | «7 дней» | «Месяц»
  (скользящие 30 полных дней) | «Период…» (два поля дат + «Применить»).
  Управляет KPI, трендом, графиком и таблицей; всё считается из уже
  расшифрованного массива в памяти — **без повторных fetch/decrypt**. Валидация
  «от ≤ до», обрезка границами данных, пустое пересечение → «Нет данных за
  период». Смена фильтра возвращает таблицу на страницу 1. Логика — единое
  `state.range` + один `applyRange()` (ADR-0002).
- **Окна KPI** (ADR-0001): якорь = min(последняя дата данных, вчера); «7 дней»
  = `[якорь−6 … якорь]`, «прошлая неделя» = `[якорь−13 … якорь−7]`. Окна по
  **календарным датам**: день без строки = вклад 0, пропуски не сдвигают
  границы (никаких `slice(-7)`). Под значением плашки — метка периода
  («за 7 дней» / «за 30 дней» / «за всё время (N дн.)» / «ДД.ММ–ДД.ММ»),
  ниже — «за 7 дней: X · к прошлой нед. ±Y%» (дельта только когда прошлое
  окно целиком покрыто данными).
- **Пагинация** (ADR-0003): 31 строка на страницу, контролы «← Назад /
  Стр. X из Y / Вперёд →» под таблицей (disabled на краях). В DOM — только
  текущая страница. Правка ячейки на любой странице обновляет строку и KPI
  точечно, страница и скролл не меняются.
- **График** (ADR-0004): окно = период фильтра; ≤90 дней — дневные столбцы и
  линии SMA7; >90 дней — ISO-недели Пн–Вс (столбцы = суммы просмотров за
  неделю, линии = доли `views/impressions` и `contacts/views` за неделю, SMA
  не рисуется, подписи X — даты начала недель); пунктиры правок — только
  внутри диапазона; перерисовка при ресайзе — throttle 150 мс + хвост.
- **Блок «Успеваемость к цели»** (ADR-0006): первый блок контента, выше KPI.
  Конфиг цели — константой в одном месте: **`GOAL = { views: 475, days: 14 }`**
  в `avito.html` (комментарий «БЛОК „УСПЕВАЕМОСТЬ К ЦЕЛИ“») — менять числа, не
  логику; правка цели из UI вне scope. Окно = активный период фильтра
  («Всё время» = последние 14 полных дней), цель окна = 475 × длина_окна/14,
  темп = Σпросмотров × 7/длина_окна, прогноз = темп × 2 (за 2 недели);
  прогноз ≥ 475 → зелёное «Успеваем», иначе красное «Не успеваем»;
  <2 дней данных в окне → «—» и серый «нет данных».
- **Конверсия «Контакт → запись»** (ADR-0007, решение владельца): только по
  **НОВЫМ** записям — `записи_новые ÷ контакты` по дате брони; в колонке
  «К→З» таблицы — `записи_новые_дня ÷ контакты_дня`; пусто/0 → «—». Старые
  клиенты (возвраты) в конверсию не входят.
- **Швы под будущий переезд** (ADR-0005): доступ к данным — модуль
  `DataLoader.load()` (сейчас fetch + WebCrypto), ручные значения —
  `ManualStore` (сейчас localStorage `avito_manual_v1`, ключ и формат не
  менять — потеря данных). Переезд на PHP/MySQL = заменить тела этих двух
  модулей, рендер не трогается. **Крипто-контракт** (PBKDF2-HMAC-SHA256
  200 000 итераций → AES-256-GCM, `data/avito.enc`, сессия `plan_pw_v1`) —
  НЕ менять.
- **Тесты приёмки**: `tests/harness.html` + синтетические фикстуры
  `tests/fixture.js` (888/1 967 показов, темп 103/нед — реальных данных
  владельца в тестах нет). Прогон:

  ```powershell
  cd C:\Users\user\Desktop\opencode\plan-dashboard
  python -m http.server 8077                       # сервер файлов для страницы
  powershell -NoProfile -ExecutionPolicy Bypass -File tests\run_harness.ps1
  ```

  Скрипт сам генерирует синтетический `tests/test.enc` (пароль тестовый,
  не секрет), поднимает endpoint отчёта на `127.0.0.1:8078` и запускает
  headless Chrome; итог — `tests/last-report.json` (`PASS=/FAIL=`). Нужны
  Chrome и Node.js; `tests/last-report.json`, `tests/test.enc` в git не идут.

### Ручные значения записей (localStorage)

- Ячейки «Записи новые»/«Записи старые» в таблице по дням — поля ввода
  (`inputmode="numeric"`, только цифры), предзаполнены данными сервера;
  колонка «Записи» = авто-сумма новых+старых, пересчёт мгновенный при вводе.
  Изменённые ячейки подсвечены оранжевым.
- Форма «+ Запись» над таблицей: **дата брони** (обязательна, по умолчанию
  сегодня) · **дата сеанса** (необязательна — можно оставить пустым) ·
  количество · тумблер новый/старый.
- Хранение: `localStorage` этого браузера, ключ `avito_manual_v1` (имя с
  версией формата), поверх серверных данных. Кнопка «Сбросить ручные значения»
  возвращает данные сервера. Плашка на странице: «Ручные значения хранятся в
  этом браузере». Пока что — локально; позже перенесётся в CRM.

### Правило дат (важно для конверсий)

- **Дата брони ≠ дата сеанса.** KPI «Контакт → запись» (НОВЫЕ записи ÷
  контакты за период — ADR-0007) считается **по дате брони** — в том числе
  записи, добавленные через «+ Запись», у которых дата сеанса выпадает из
  периода.
- Строка таблицы = **дата сеанса**, если указана, иначе дата брони; колонка «К→З»
  в строке — `записи_новые_дня ÷ контакты_дня` по данным этой строки
  (даты брони у серверных строк нет).
- Серверные `rows` формирует календарь **по дате сеанса**: записи на сеансы вне
  периода в них не видны — вносите их через «+ Запись» с датой брони.
- В будущей CRM у записи будут **обе даты**; на границе периода KPI «Контакт →
  запись» (по дате брони) и суммы по строкам таблицы (по дате сеанса) могут
  слегка расходиться — это ожидаемо.

## Безопасность

- Пароль владелец держит сам: не в репо, не в `.env`, не в скриптах, не в логах.
- Соль и IV случайные при каждом шифровании — один и тот же план даёт разный шифротекст.
- AES-256-GCM с auth-tag: неверный пароль и порча файла дают одну ошибку — «неверный пароль».
- Страница отдаётся по HTTPS; расшифровка только на клиенте, сервер plaintext не видит.
- Ограничение: пароль можно перебирать брутфорсом (файл публичный) — используйте длинный
  пароль (12+ символов).
