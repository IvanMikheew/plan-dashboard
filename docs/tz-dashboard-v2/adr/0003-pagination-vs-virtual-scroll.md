# 0003. Пагинация таблицы (31 строка), а не виртуальный скролл

- **Статус:** принято
- **Дата:** 2026-11-26
- **Контекст:** таблица растёт с данными (месяц ≈ 30 строк, год = 365); владелец просит
  листание по 31 строке («31 строка ≈ месяц») и сам определил поведение: «больше 31
  строки — новая страница». Работаем на телефоне, без фреймворков, всё в одном HTML.
- **Варианты:**
  1. **Пагинация 31 строка/страница** (кнопки «Назад/Вперёд» + счётчик): плюсы — ровно по
     требованию; DOM всегда ≤31 строки (телефону легко); тривиально тестируется; минус —
     листание вместо бесконечного скролла, на каждой странице заново рисуются строки.
  2. Виртуальный скролл (рендер видимых строк): плюс — «бесконечная» лента; минус —
     существенно больше кода (измерение строк, якоря скролла), хрупко на мобильных
     тач-событиях, противоречит требованию владельца про листание.
  3. «Показать ещё» (инкрементальная догрузка): минус — DOM растёт сессией, при 365
     строках таблица перестаёт быть управляемой, счётчик «≈ месяц» не нужен владельцу.
- **Решение:** вариант 1. Сортировка — как сейчас, новые сверху; стр. 1 = самые новые
  31 строка; «Назад» = старее. Смена фильтра → стр. 1; правка ячейки/«+ Запись» → страница
  сохраняется (точечное обновление строки + KPI, без перерисовки таблицы).
- **Последствия:** при росте до нескольких лет меняем только размер страницы/контролы
  (код пагинации не зависит от объёма); редактирование ячеек должно работать точечно —
  это зафиксировано в критериях приёмки. Минус: владельцу, привыкшему к скроллу, нужно
  одно лишнее нажатие — принято осознанно.

  `avito.html` (`components/Pager`, таблица в `render`).
