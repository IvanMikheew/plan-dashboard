# 0005. Швы под будущий переезд: DataLoader и ManualStore; крипто-контракт не трогаем

- **Статус:** принято
- **Дата:** 2026-11-26
- **Контекст:** направление роста владельца: хостинг Reg.ru (PHP/MySQL), CRM, онлайн-запись;
  ручные значения сегодня — localStorage (`avito_manual_v1`, две даты: брони bd и сеанса sd).
  При этом крипто-контракт `data/*.enc` ↔ `tools/crypt.js` ↔ страницы — работающий и святой
  (менять только через ADR с миграцией и откатом). Риск без швов: при переезде придётся
  выковыривать fetch/decrypt и localStorage из рендера — ломая всё сразу.
- **Варианты:**
  1. **Два модуля-шва без смены реализации:** `DataLoader.load() → {updated, rows, edits}`
     (сейчас — fetch + WebCrypto, код шифрования переносится байт-в-байт) и `ManualStore`
     (сейчас — localStorage). Плюсы — будущий переезд = замена 2 модулей + серверное API,
     рендер не трогается; минус — небольшой рефакторинг без видимой пользы «сегодня».
  2. Сразу строить слой PHP/MySQL (REST, схема БД): плюс — «всё готово»; минус — YAGNI:
     хостинга, схемы CRM и решений по авторизации ещё нет; строить вслепую = выбросить.
  3. Оставить как есть (fetch/decrypt и localStorage размазаны по коду): минус — стоимость
     переезда кратно вырастет.
- **Решение:** вариант 1. Реализации не меняем: `.enc`/PBKDF2(200 000)/AES-256-GCM, ключ
  localStorage `avito_manual_v1`, форматы JSON — без изменений; в комментариях швов —
  будущий контракт для CRM (запись = `{bd, sd, q, t}`, обе даты обязательны). Крипто на
  будущем хостинге: сохранить клиентское шифрование или перевести на HTTPS+auth —
  отдельным ADR на момент переезда (миграция данных обязательна).
- **Последствия:** любая новая фича ходит к данным только через `DataLoader`/`ManualStore`;
  ключ `avito_manual_v1` не переименовывать (потеря данных у владельца) — смена схемы =
  новый ключ + миграция через ADR; переезд на Reg.ru не потребует переписывать UI.
  Минус: два лишних абстрагирующих слоя в одном файле — оправданы уже заявленным
  направлением роста (в отличие от гипотетических сервисов).
- **Связи:** SPECIFICATION.md §1, R4; IMPLEMENTATION.md §1, §5; TASKS.md TASK-5;
  файлы: `avito.html` (секции `loader`, `manual`), `tools/crypt.js` (не меняется).
