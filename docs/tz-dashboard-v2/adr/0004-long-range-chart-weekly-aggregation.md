# 0004. График под фильтром: ≤90 дней — дни со SMA7, >90 дней — ISO-недельные бакеты

- **Статус:** принято
- **Дата:** 2026-11-26
- **Контекст:** график сейчас фиксированные 28 дней; по требованию R2 он должен
  отображать диапазон фильтра, включая «всё время» (год = 365 точек). Дневной ряд из
  365 столбцов на телефоне (~300px) = столбцы <1px — нечитаемо. Внешних библиотек нет
  (ограничение: один HTML, без фреймворков).
- **Варианты:**
  1. **Недельная агрегация при >90 дней** (ISO-недели Пн–Вс: столбцы = суммы просмотров,
     линии = доли за неделю, SMA отключается): плюсы — читаемо на любом экране, код один
     (тот же canvas-рендер, другие бакеты); минус — теряется дневная детализация
     (но она доступна в таблице и при выборе ≤90 дней).
  2. Дневные столбцы всегда, просто уже: плюс — просто; минус — на 365 днях график
     превращается в «шум», это плохая визуализация, а не простота.
  3. Зум/панорамирование (drag, pinch): плюс — детализация всегда; минус — заметно больше
     кода, хрупко на тач, не требуется владельцу.
- **Решение:** вариант 1. Порог 90 дней; неполные недели по краям диапазона — как есть;
  подписи оси X — даты начал недель; маркеры правок — только внутри диапазона. Дебаунс
  resize 150 мс — требование R4 (телефон).
- **Последствия:** при сравнении «неделя к неделе» на длинном диапазоне график уже
  недельный — это совпадает с моделью дельт (ADR-0001); при появлении запроса «дни на
  годовом графике» — либо вариант 3 отдельным ADR, либо выбор диапазона ≤90 дней.
  Минус: две ветки рендера (дни/недели) — их надо тестировать обе (критерии TASK-4).
- **Связи:** SPECIFICATION.md R2/R4, IMPLEMENTATION.md §3.4; TASKS.md TASK-4; файлы:
  `avito.html` (`drawChart`).
