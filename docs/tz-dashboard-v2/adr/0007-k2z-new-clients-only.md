# 0007. Конверсия «Контакт → запись» — только по НОВЫМ клиентам

- **Статус:** принято (решение владельца, без system-architect — указание владельца)
- **Дата:** 2026-11-26
- **Контекст:** SPECIFICATION.md R1/R4 определяет KPI «Контакт → запись» как
  «записи ÷ контакты» — вместе со старыми клиентами. Владелец уточнил: старые
  записи — это возвраты, а не конверсия трафика; в воронке «просмотр → клиент»
  (baseline ≈ 2%) интересуют только новые клиенты.
- **Решение:**
  1. KPI «Контакт → запись» = **записи_новые ÷ контакты** (по дате брони bd;
     «+ Запись» учитывается только с `t = 'new'`). Записи_новые пусты или 0 →
     значение «—».
  2. Колонка «К→З» таблицы по дням = **записи_новые_дня ÷ контакты_дня**;
     пусто/0 → «—». Обновление ячейки (refreshRow) — та же формула.
  3. KPI «Записи» / «Записи новые» / «Записи старые», ручной слой
     (`avito_manual_v1`), блок «Успеваемость к цели» (R5 — по показам) и
     крипто-контракт — **без изменений**.
- **Последствия:** семантика конверсии изменена на уровне одной метрики
  (`mK2Z()` в `avito.html`); 7-дневная строка и дельты используют ту же
  метрику окна, автоматически. README описывает новую формулу. Отменяется
  только формула — форматы данных и ADR-0001..0006 остаются в силе.
- **Связи:** SPECIFICATION.md R1 (значение/метки), §5 (форматы — без изменений);
  TASKS.md TASK-1 (kpis/fillSub) и TABLE «К→З»; файлы: `avito.html`
  (`mK2Z`, рендер таблицы, `refreshRow`), `README.md`.
