# 0001. Окна KPI считаются по календарным датам в слое селекторов, дельта — всегда «к прошлой неделе»

- **Статус:** принято
- **Дата:** 2026-11-26
- **Контекст:** плашка «за 7 дней» показывает сумму всего периода (1 967 при ~888 за
  7 дней); дельты считаются `rows.slice(-7/-14)` — по индексам строк, поэтому пропуски дат
  и «хвост» данных сдвигают окна. Требование владельца: «7 дней = последние 7 полных дней;
  дельта = предыдущие 7». Данные растут (год = 365 строк), окна нужны и фильтрам (ADR-0002).
- **Варианты:**
  1. **Календарные окна в чистых селекторах** (`windowRows(rows, from, to)`, якорь
     `min(последняя дата данных, вчера)`): плюсы — честные окна при пропусках дат,
     переиспользуются фильтрами/графиком, тестируются на фикстуре; минусы — чуть больше кода.
  2. Лечить подписи только («за весь период» вместо «за 7 дней»): плюс — минимально;
     минус — не выполняет требование владельца (7-дневные цифры всё равно нужны).
  3. Окна по индексам строк как сейчас, но с фильтром `length`: дёшево, но остаётся сдвиг
     при пропусках — баг воспроизводится.
- **Решение:** вариант 1. Якорь = `min(последняя дата в данных, сегодня−1)` — «полные дни»,
  детерминирован при отстающих данных. Подпись плашки = метка активного периода + строка
  «за 7 дней: X · к прошлой нед. ±Y%» (окна `[anchor−6..anchor]` и `[anchor−13..anchor−7]`);
  для %-KPI дельта остаётся относительной (не меняем семантику без спроса — открытый
  вопрос SPEC §7.3).
- **Последствия:** любой новый агрегат обязан идти через селекторы окон, а не `slice`;
  день без строки = вклад 0/null (это часть контракта); при появлении данных «в будущем»
  (ошибочные даты) якорь защитит от неполных окон. Минус: 7-дневная строка на плашках —
  лишняя строка UI (компактность решается версткой, не логикой).
