- **Статус:** на согласовании · **Дата:** 2026-11-26
- **Вход:** [SPECIFICATION.md](SPECIFICATION.md) · **Выход:** [TASKS.md](TASKS.md) · ADR: `adr\`
- **Исполнитель:** dev-backend (PowerShell/JS/HTML, без фреймворков, один файл `avito.html`)

## 1. Структура кода (внутри `avito.html`, без новых файлов рантайма)

Страница остаётся одним HTML; внутри — секции-модули с чистыми функциями (порядок сверху вниз):

| Секция | Содержимое | DOM? |
|---|---|---|
| `selectors` | `rangeAnchor(rows)`, `windowRows(rows, from, to)`, `filterRows(rows, range)`, `prev7(range/anchor)`, `aggregate(rows)` (sum/rate) | нет |
| `manual` (`ManualStore`) | load/save/cellOverride/add/clear поверх localStorage `avito_manual_v1` | нет |
| `loader` (`DataLoader`) | fetch `data/avito.enc` → decrypt → `{updated, rows, edits}`; **код шифрования не трогать** | нет |
| `state` + пайплайн | `state = {range, page}`; `applyRange()` = effRows → filterRows → прогнать KPI/chart/table | — |
| `components` | `PeriodFilter` (пресеты + from/to), `Pager` (31/стр, назад/вперёд, счётчик) | да |
| `render` | KPI-плашки, тренд, график (canvas), таблица; точечные апдейты `refreshRow/refreshKpis` | да |

Текущие функции `kpis/fillSub/delta7/drawChart/render` перерабатываются на эту структуру,
поведение старых мест фиксируется регрессионным чек-листом (§5).

## 2. Поток данных

```
DataLoader.load() ─→ raw {updated, rows, edits}          (один раз за сессию)
ManualStore.load() ─→ manual {cells, adds}                (один раз; правки — на месте)
        └─→ effRows(rows) = сервер + cells + adds         (как сейчас, правило bd/sd)
state.range ─→ filterRows(eff, range) ─→┬→ aggregate → KPI-плашки (+7-дневная строка)
                                        ├→ chartSeries(range ≤90 дн. — дни; >90 — ISO-недели)
                                        └→ tableRows → Pager(page) → 31 строка DOM
```

Всё считается из памяти; смена фильтра/страницы = повторный проход по массиву (O(n)),
без fetch/decrypt и без пересборки ручного слоя.

## 3. Ключевые правила реализации

1. **Окна — по календарным датам** (ADR-0001): якорь `min(последняя дата данных, вчера)`;
   окна `[anchor−6..anchor]` и `[anchor−13..anchor−7]`; пропуски дат = вклад 0/null.
   Никаких `slice(-7)` по строкам.
2. **Фильтр** (ADR-0002): `state.range = {from: 'ГГГГ-ММ-ДД'|null, to: ...}` (null = границы
   данных); пресеты выставляют range; «Период…» валидирует `от ≤ до`; один `applyRange()`
   на смену любого состояния.
3. **Пагинация** (ADR-0003): 31 строка, `state.page`, сброс страницы при смене range.
4. **График** (ADR-0004): окно = `state.range`; ≤90 дней — текущий дневной вид со SMA7;
   >90 — ISO-недельные бакеты (столбцы = суммы просмотров, линии = `views/impressions`,
   `contacts/views` за неделю, SMA отключается); маркеры правок — только внутри диапазона;
   resize — debounce 150 мс.
5. **Швы под будущее** (ADR-0005): `DataLoader` и `ManualStore` — единственные места,
   знающие про `.enc` и localStorage; будущий Reg.ru/PHP = замена этих двух модулей +
   серверное API. Реализации на PHP/MySQL сейчас не пишем.
6. **Производительность:** DOM таблицы ≤31 строки; `refreshKpis` — точечное обновление
   текста плашек; график — только по debounce; не оптимизировать сверх этого (измеримость
   не требуется: n ≤ 2000).

## 4. Порядок работ (строгая цепочка)

1. **TASK-1** — селекторы окон + баг-фикс R1 (фундамент: календарные окна, метки, 7-дневная строка).
2. **TASK-2** — фильтры R2 (state + `applyRange` + `PeriodFilter`) — на селекторах TASK-1.
3. **TASK-3** — пагинация R3 (`Pager`) — на отфильтрованных строках TASK-2.
4. **TASK-4** — график под фильтром + недельная агрегация + resize-debounce — на range TASK-2.
5. **TASK-5** — швы `DataLoader`/`ManualStore` + README + регрессионный прогон — финал.

Каждая задача = один PR-объём; после каждого — страница рабочая (малые обратимые шаги).

## 5. Что НЕ ломать (регрессионный чек-лист — пройти в TASK-5)

- [ ] `data/avito.enc` открывается существующим паролем; формат base64(salt16‖iv12‖ct+tag),
      PBKDF2 200 000 / SHA-256 → AES-256-GCM — без изменений (дифф секции крипто = пуст).
- [ ] Сессия `plan_pw_v1`: переход из `index.html` — авто-вход работает.
- [ ] localStorage `avito_manual_v1`: ранее сохранённые правки и «+ Запись» читаются и
      отображаются (ключ и формат не менялись).
- [ ] Правило дат: конверсия «Контакт → запись» — по дате брони (adds по `bd`); строка
      таблицы — по `sd`, иначе `bd`.
- [ ] Правка ячейки «Записи новые/старые»: очистка = возврат к серверному значению;
      введённое = итог (правка = введённое − добавленные) — семантика `cellInput` сохранена.
- [ ] «+ Запись» и «Сбросить ручные значения» работают; статус-строка показывает результат.
- [ ] Ошибка пароля → «Неверный пароль»; нет файла → «Не удалось загрузить».
- [ ] Тёмная/светлая тема, мобильная вёрстка, aria-подписи таблицы — без регрессий.

## 6. Проверка окон на фикстуре (TASK-1, обязательна)

Тестовый набор (инъекция `rows` в консоль/временный объект, без git): строки за ~37 дней,
где Σ показов за `[anchor−6..anchor]` = 888, Σ за весь период = 1 967, с 2–3 пропусками
дат внутри окон. Сверить: значение/метка/7-дневная строка плашек (SPEC R1), дельта =
(Σ окна − Σ пред. окна)/Σ пред. окна. Ручной пересчёт — в отчёте задачи.
