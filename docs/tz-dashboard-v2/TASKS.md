## TASK-1. Селекторы календарных окон + баг-фикс «за 7 дней» и дельт

**Файлы:** `avito.html` (секция UI: `selectors`, правки `kpis`, `fillSub`, `delta7`, `render`).
**Зависимости:** нет (первая).
**Контекст:** сегодня `delta7` режет массив строк (`slice(-7)`), а плашка подписанная
«за 7 дней» показывает сумму всего периода (1 967 вместо 888). Определения окон —
SPECIFICATION.md §3–4 (R1), ADR-0001.

**Что сделать:**
1. Чистые функции без DOM: `rangeAnchor(rows)` → `min(последняя дата, вчера)`;
   `windowRows(rows, from, to)` → строки с датами в `[from..to]` включительно;
   `agg7(rows)` → `{value7, valuePrev7, delta}` по правилам §3 (день без строки = вклад 0).
2. KPI-плашки по R1: значение = за весь период (фильтра ещё нет — период = данные),
   метка «за всё время (N дн.)», строка «за 7 дней: X · к прошлой нед. ±Y%» (X и Y из окон
   §3; нет окна сравнения → только X; нет данных → «нет данных»). Для %-KPI X — доля за
   окно, Y — относительная дельта (семантика как сейчас). «Записи новые/старые»: sub
   «за период» → тот же формат. Метка периода — отдельной строкой от дельты.
3. `delta7` (slice-версию) удалить или переписать на окна; `fillSub` — на новую строку.

**Критерии приёмки:**
- [ ] Фикстура (IMPLEMENTATION.md §6): Σ7дн = 888, Σпериод = 1 967 → плашка «Показы»:
      значение 1 967, метка «за всё время (37 дн.)» (N — число дней в данных), строка
      «за 7 дней: 888 · к прошлой нед. ±Y%» с Y по ручному расчёту (±1 п.п. округления).
- [ ] Пропуски дат внутри окон не сдвигают границы (проверить на фикстуре с пропусками).
- [ ] Меньше 14 дней данных → «за 7 дней: X» без дельты (или «нет данных» при пустом окне).
- [ ] Правка ячейки/«+ Запись» → плашки пересчитываются с новыми окнами (refreshKpis).
- [ ] Крипто-секция и localStorage-контракт не тронуты (дифф пуст).

## TASK-2. Фильтр периода: пресеты + произвольный диапазон

**Файлы:** `avito.html` (секции `state`, `components/PeriodFilter`, `render`, `selectors`).
**Зависимости:** TASK-1 (окна/селекторы).
**Контекст:** SPECIFICATION.md R2, ADR-0002. Данные — только из расшифрованного массива
в памяти (`lastData`), без повторного fetch/decrypt.

**Что сделать:**
1. `state.range = {from, to}` (null = границы данных) + `applyRange()`: effRows →
   filterRows(range) → перерисовать KPI/тренд/график/таблицу. Одна точка входа на все
   перерисовки от фильтра.
2. UI-компонент `PeriodFilter` под topbar: «Всё время» (дефолт) | «7 дней» | «Месяц»
   (= `[anchor−29..anchor]`) | «Период…» → два `input[type=date]` + «Применить».
   Активный пресет визуально выделен; при ручном диапазоне активен «Период…».
3. Метки периодов на плашках под фильтром: «за 7 дней» / «за 30 дней» /
   «за всё время (N дн.)» / «ДД.ММ–ДД.ММ». 7-дневная строка (TASK-1) сохраняется;
   при активном окне 7 дней — дельта без дублирования X (SPEC R1).
4. Валидация: `от ≤ до`; ограничение диапазоном данных; пустое пересечение →
   «Нет данных за период» (блок тренда/KPI/графика/таблицы — как текущий `render` при
   пустых данных). Смена фильтра → `state.page = 1` (пагинация TASK-3, заготовка).

**Критерии приёмки:**
- [ ] Все 4 режима переключают KPI + тренд + график + таблицу без повторной расшифровки
      (в консоли нет fetch/decrypt при смене фильтра).
- [ ] «7 дней» = последние 7 полных дней (сверить с ручной суммой фикстуры = 888).
- [ ] «Месяц» = 30 полных дней; «Период…» — произвольный диапазон, значения из данных.
- [ ] `от > до` → сообщение, значение не применяется; даты вне данных ограничиваются.
- [ ] Пустой диапазон → «Нет данных за период», страница не ломается, фильтр переключается.
- [ ] Дефолт «Всё время» = текущие цифры без фильтра (регрессия: совпадает с TASK-1).
- [ ] Крипто-секция и `avito_manual_v1` не тронуты.

## TASK-3. Пагинация таблицы (31 строка на страницу)

**Файлы:** `avito.html` (секции `components/Pager`, `render/таблица`).
**Зависимости:** TASK-2 (`state.range`, сброс страницы).
**Контекст:** SPECIFICATION.md R3, ADR-0003. Сортировка — как сейчас, новые сверху.

**Что сделать:**
1. `Pager`: 31 строка на страницу; `state.page`; контролы под таблицей: «← Назад»,
   «Стр. X из Y», «Вперёд →» (кнопки с состоянием disabled на краях; тач-таргеты ≥40px).
   Стр. 1 = самые новые 31 строка; «Назад» = старее.
2. Рендер таблицы — только текущая страница (31 `<tr>` в DOM). Редактирование ячеек
   «Записи новые/старые» на любой странице: после правки — точечное обновление строки и
   KPI, страница и скролл не меняются (перерисовка всей таблицы не нужна).
3. Смена фильтра (TASK-2) → стр. 1; правка ячейки/«+ Запись» → страница сохраняется.

**Критерии приёмки:**
- [ ] 32 строки в фильтре → 2 страницы (31+1), счётчик «Стр. 1 из 2», листание работает
      в обе стороны, на краях кнопки disabled.
- [ ] 31 строка → 1 страница, листание недоступно; 0 строк → «Нет данных за период».
- [ ] В DOM таблицы не больше 31 строки данных на любой странице.
- [ ] Правка ячейки на стр. 2: значение сохраняется (localStorage), KPI обновляются,
      активная страница — 2.
- [ ] Смена фильтра → возврат на стр. 1.

## TASK-4. График под фильтром + недельная агрегация + resize-debounce

**Файлы:** `avito.html` (секция `render/chart`, `drawChart`).
**Зависимости:** TASK-2 (`state.range`).
**Контекст:** SPECIFICATION.md R2/R4, ADR-0004. Сейчас график — фиксированные 28 дней.

**Что сделать:**
1. Окно графика = `state.range` (не 28 дней); заголовок карточки отражает диапазон.
2. ≤90 дней в диапазоне — текущий дневной вид (столбцы просмотров, линии CTR и
   «просмотр→контакт» SMA7, правая ось %, подписи дат каждые 4 дня).
3. \>90 дней — ISO-недельные бакеты (Пн–Вс): столбцы = суммы просмотров за неделю,
   линии = `views/impressions` и `contacts/views` за неделю, SMA не рисуется, подписи оси X
   — даты начала недель; неполные недели по краям диапазона — как есть.
4. Маркеры правок (`edits`) — пунктиры только для дат внутри диапазона.
5. ResizeObserver → debounce 150 мс (перерисовка не чаще 1 раза в 150 мс при
   перетаскивании/повороте экрана).

**Критерии приёмки:**
- [ ] Переключение фильтров меняет окно графика (7 дней → 7 столбцов; произвольный
      диапазон → его дни).
- [ ] Диапазон 90 дней → дневной режим; 91+ дней → недельные бакеты (проверить на
      синтетических данных за 6 месяцев: число столбцов ≈ числу ISO-недель).
- [ ] Легенда/подписи корректны в обоих режимах; SMA7 не рисуется в недельном режиме.
- [ ] Правка вне диапазона не даёт маркер; внутри — да.
- [ ] Поворот телефона/ресайз окна: перерисовка ≤ 1 раза в 150 мс, визуально без мерцания.

## TASK-6. Блок «Успеваемость к цели» (+475 показов за 2 недели)

**Файлы:** `avito.html` (новая секция `goal` — чистый расчёт + блок UI в `render`,
пересчёт в `applyRange`), `README.md` (конфиг цели, где менять числа).
**Зависимости:** TASK-1 (календарные селекторы), TASK-2 (`state.range`, `applyRange`).
**Контекст:** SPECIFICATION.md R5 (добавлено 2026-11-26), ADR-0006. Цель: +475 показов за
14 дней (нужный темп 237,5/нед); конфиг одной константой `GOAL = {views: 475, days: 14}`.

**Что сделать:**
1. Чистая функция `goalStats(rows, range, anchor)` → `{fact, target, pace, needPace,
   forecast, verdict}` по семантике R5/ADR-0006: окно = активный период («Всё время» =
   окно цели `[anchor−13..anchor]`); `target = 475 × длина_окна/14`; `pace =
   Σпросмотров_окна × 7/длина_окна` (показов/нед); `needPace = 475 × 7/14 = 237,5/нед`;
   `forecast = pace × 2`; `verdict = forecast ≥ 475 ? 'ok' : 'late'`; <2 дней в окне →
   значения «—», `verdict = 'nodata'`.
2. Блок UI **первым в контенте, выше KPI-плашек**: заголовок «Успеваемость к цели: +475
   показов за 2 недели»; строки (а) «текущий темп: 103/нед», (б) «нужный темп: 237,5/нед»,
   (в) прогресс-бар «накоплено X из Y» (div-бар, `role="progressbar"` +
   `aria-valuenow/min/max`; X > Y → 100% + фактическое число), (г) «при текущем темпе
   через 2 недели будет 206», (д) вердикт-плашка: зелёная «Успеваем» / красная «Не
   успеваем» (серый «нет данных»).
3. Пересчёт блока в `applyRange()` при смене фильтра. Ручной слой (bookings) на блок не
   влияет (цель — по показам) — доп. пересчёт не нужен.

**Критерии приёмки:**
- [ ] Фикстура «темп 103/нед» (Σ последних 7 полных дней = 103): темп «103/нед», нужный
      темп «237,5/нед», прогноз «через 2 недели будет 206», вердикт красный «Не
      успеваем»; прогресс-бар = Σ за 14 дней из 475 (значения сверены вручную).
- [ ] Смена фильтра пересчитывает блок по R5: «7 дней» → цель окна 237,5; «Месяц» →
      цель окна ≈ 1018 (475×30/14), темп = Σ30дн×7/30; «Период…» (5 дней) → цель окна
      ≈ 170; «Всё время» → окно цели 14 дней, цель 475.
- [ ] Вердикт: прогноз ≥ 475 → зелёный «Успеваем», иначе красный «Не успеваем» — оба
      случая проверены на фикстуре; при <2 днях данных → «—» и серый «нет данных».
- [ ] Прогресс-бар: aria-атрибуты заполнены; при X > Y — 100% + фактическое число.
- [ ] Блок — первый на странице (выше KPI); на телефоне вёрстка не ломается.
- [ ] Окна считаются по календарным датам (ADR-0001): пропуски дат не сбивают расчёт.
- [ ] Крипто-секция и `avito_manual_v1` не тронуты.
